# Known Issues (backlog)

Found during the 2026-09-26 cleanup and while writing these docs, mostly by reading code. Unless marked **verified**, an item has not been reproduced in game: confirm it with a log before fixing (see [DEVELOPMENT.md](DEVELOPMENT.md#verifying-a-change-in-game)). Items are numbered for reference. Remove an item when it is fixed.

Fixed on 2026-09-26, for reference: `SkyrimNetDiaries_API.pex` had never shipped, so the theft decorator always returned None (**verified**, user report). Template lookup in `CreateDiaryBook` now uses `LookupByEditorID`, so powerofthree's Tweaks alone is enough (**verified**: before the change every creation failed without Native EditorID Fix, or with it installed but its `EnableNativeEditorIDLookup` off: 1.x scanned books by `GetFormEditorID()`, which needs that setting. SkyrimNet used to turn it on and no longer does, and Nolvus ships it off; seen again on SE 2026-10-09). New entries for ESL and high load-order NPCs never reached a book: the event listener converted `actorFormId` with `as int`, which clamps FormIDs of `0x80000000` and up to `0x7FFFFFFF` (**verified**: "Could not resolve FormID 0x7FFFFFFF"). The listener now passes the JSON to the `UpdateDiaryFromEvent` native, which parses it in C++. Loading an older save built books before the player answered SkyrimNet's keep/clear prompt, so a Clear left a blank book behind and the next entry added a second volume 1 (**verified**, SkyrimNet and SNPD logs); the post-load sync now waits for the answer (`TimelineGate`), ignores diary events until it has run, and the stale-endTime rebuild removes the old books from the NPC's inventory. The save folder is now detected after those waits, so the previous save's DB is no longer picked up. Fixed on 2026-09-27: sealing or updating a volume, refreshing it on open and MCM Regenerate asked SkyrimNet for `EntriesPerVolume + 1` entries and treated them as the oldest, but SkyrimNet's limit keeps the newest, so when entries piled up behind a volume its first entries vanished from every book (`Database::GetVolumeEntries` now fetches the whole range and caps afterwards). The update query now passes the volume's boundary data, and the first overflow volume after a seal gets boundary data too, so an entry sharing the boundary date is no longer rendered in two volumes. Also fixed that day: an NPC could get two sets of volumes ("four diaries, each name twice", **verified**) because nothing tracked volumes still being created, so recovery, catch-up and diary events each created the same volumes; creations are now counted per actor and cancelled at every load and Reset. The create queue no longer stalls after a failed dispatch or when a load drops an in-flight Create(). DiaryDB is closed at kPreLoadGame, the co-save's folder name is ignored, a new game's first save marks its volumes persisted, volumes that reach past a loaded save are reconciled with the history SkyrimNet kept or cleared (ReconcileWithTimeline, replacing the game-time stale rebuild, which missed saved volumes after an in-session revert and dropped new entries), an empty template name no longer blocks an actor, and the actor cache and book timers hold FormIDs instead of pointers. Crash-proofing: exceptions can no longer escape into the engine from the book-open hook, the post-load sync (which now always re-enables diary events), the save and load callbacks, the theft event sink, the Papyrus natives, the inter-plugin handler or the SkyrimNet API wrappers. Config values are clamped when read, so EntriesPerVolume = 0 in the INI no longer hangs the game, and a non-numeric INI value no longer wipes the INI on the next save. Identity: theft and return detection work in every language (the English "Diary" name filter and the name-in-title owner fallback are gone; volumes are found by base FormID and owners by UUID), the Nightingale journal is chosen by base NPC instead of English name, a book opened after a load-order change no longer shows another actor's entries (the stored actor FormID is checked against the UUID), and the two startup warnings are localized. Text: dates use Skyrim's real month lengths instead of 30-day months; diary prose is escaped for the book markup (a "<" no longer swallows text, and a literal [pagebreak] can't shift the API's entry numbering); Win-1251 conversion only runs on Cyrillic text (French «» are no longer mangled) and now also maps „ and №; the inter-plugin API header describes what the handlers actually return. A volume whose entries were all deleted outside a load now shows the "all entries removed" page instead of its old text; a failed SkyrimNet query (now reported separately from zero entries) keeps the cached text. A New Game started after loading a save now ends the session like a load does (before, it kept writing into the previous character's DiaryDB). Lowering EntriesPerVolume no longer cuts entries from existing volumes: a volume's size comes from its stored boundaries. A failed query no longer makes ReconcileWithTimeline delete volumes or MCM Regenerate render the "all entries removed" page. Loading an earlier save drops only the thefts made after it (by `stolen_at`), not all of an actor's thefts; `last_known_game_time` is no longer used. A load or new game during the catch-up scan drops the rest of the scan instead of creating duplicate volumes. A recycled FormID the same actor already owns is now rejected too, and a new volume's text is written to the volume just registered, not the first one with that FormID. If the post-load sync can't load this save's volumes (no save folder, no DPF, SkyrimNet not ready), diary books pause for the session instead of creating a second set; SaveCallback no longer opens a DB during the post-load wait. The latest volume no longer ends in a blank page when a newer entry exists. A volume newer than the loaded save that a later save included is given back to the NPC after Keep. Also that day: the kCantTake clears share one timer thread instead of one sleeping thread per book; GetBookForFormID uses a FormID index instead of scanning every volume; the OpenBookMenu hook is a MinHook detour instead of a hand-written prologue decoder; "sealed" means only "hit the entry limit" (QueueSealedVolumeRecovery is now QueueNewEntryRecovery); the co-save writes no records; the version was set to 1.2.0 (released as 2.0.0). Removed on 2026-09-27 as well: the `SkyrimNetDiaries_API` Papyrus script (never shipped working, no callers) and with it the `"chronicled"` field; the unused `SNPD_DiaryStolenFaction` ESP record stays (harmless). The theft prompt's dependency on SkyrimNet's prompt layout is documented in THEFT.md instead of here. Also removed that day: the in-game `ExtraUniqueID` probe, the unused `DPF_API` shim, the `PhysicalDiaryAPI` and `GetStolenFaction` natives, a log-only duplicate container sink and the `SNDC` co-save cache it fed, Dynamic Book Framework-era `.txt` cleanup, and about a dozen uncalled functions.

Fixed on 2026-09-28 (2.0.0): Dynamic Persistent Forms is replaced by runtime forms the engine saves itself (see [BOOK_FORMS.md](BOOK_FORMS.md)). This removed the DPF workarounds (create queue, FormID claims, pending creations, `kCantTake` timer, VR `sourceFiles` fix, `persisted_in_save` and the inventory re-add) and fixed two issues: **Reset left books in unloaded cells as orphans showing their template's text** (books are now retired: every copy is removed as soon as it can be reached, at retirement or when its cell loads; the invisible form stays in the save), and **a DPF FormID could mean different diaries in different saves** (a book's FormID now belongs to one save's timeline, and the save's own record says which volume it is). ## Likely bugs (user-facing)

8. **A renamed NPC gets a second set of diary books** (read from the code on both sides, not reproduced in game). SkyrimNet's UUID is a hash of the display name and FormID, so a rename (NND, the player) gives the actor a new UUID; the old one becomes a "former self" that diary reads merge back in. SNPD keys volumes by UUID: the NPC's next entry finds no volumes under the new UUID and builds a full set from volume 1 out of every entry, both selves', while the old books stay in their inventory. The old UUID still maps to the same FormID (`PublicUUIDToFormID`), so the old chain's open-ended latest volume also shows the new self's entries. Fix idea: when a FormID's current UUID has no volumes, find the chain whose UUID maps to the same FormID and re-key it (DiaryDB rows and the books' `VolumeKey`s) to the new UUID and name.

## By design

9. **Identity-linked NPCs share their diary books.** SkyrimNet treats an actor's co-identity set (former selves after a rename, declared successions, identity links) as one journal: its diary reads, prompts and memories all merge them. SNPD's books show that same journal, so with a bidirectional link each NPC's books also hold the other's entries, with no author shown. Things a player may notice: adding a link mid-playthrough brings the other self's whole history into the existing volumes at once, and removing it takes those pages away. A change belongs in SkyrimNet's identity links, not in SNPD.


10. **A blank journal written in, then a Keep, leaves both.** Reloading a save from before the blank was written in, and choosing SkyrimNet's Keep, restores the journal it became ([EDITING.md](EDITING.md#diaries-and-journals)) while the save still has the blank: one blank turned into a journal and a blank. Taking a matching blank from the player's inventory on restore was considered (2026-10-08) and left out: it misses a blank stashed in a chest, and the dupe is a cheap item, the cost of time travel.
