# Known Issues (backlog)

Found during the 2026-09-26 cleanup and while writing these docs, mostly by reading code. Unless marked **verified**, an item has not been reproduced in game: confirm it with a log before fixing (see [DEVELOPMENT.md](DEVELOPMENT.md#verifying-a-change-in-game)). Items are numbered for reference. Remove an item when it is fixed.

Fixed on 2026-09-26, for reference: `SkyrimNetDiaries_API.pex` had never shipped, so the theft decorator always returned None (**verified**, user report). Template lookup in `CreateDiaryBook` now uses `LookupByEditorID`, so powerofthree's Tweaks alone is enough (**verified**: before the change every creation failed without Native EditorID Fix). New entries for ESL and high load-order NPCs never reached a book: the event listener converted `actorFormId` with `as int`, which clamps FormIDs of `0x80000000` and up to `0x7FFFFFFF` (**verified**: "Could not resolve FormID 0x7FFFFFFF"). The listener now passes the JSON to the `UpdateDiaryFromEvent` native, which parses it in C++. Loading an older save built books before the player answered SkyrimNet's keep/clear prompt, so a Clear left a blank book behind and the next entry added a second volume 1 (**verified**, SkyrimNet and SNPD logs); the post-load sync now waits for the answer (`TimelineGate`), ignores diary events until it has run, and the stale-endTime rebuild removes the old books from the NPC's inventory. The save folder is now detected after those waits, so the previous save's DB is no longer picked up. Fixed on 2026-09-27: sealing or updating a volume, refreshing it on open and MCM Regenerate asked SkyrimNet for `EntriesPerVolume + 1` entries and treated them as the oldest, but SkyrimNet's limit keeps the newest, so when entries piled up behind a volume its first entries vanished from every book (`Database::GetVolumeEntries` now fetches the whole range and caps afterwards). The update query now passes the volume's boundary data, and the first overflow volume after a seal gets boundary data too, so an entry sharing the boundary date is no longer rendered in two volumes. Also fixed that day: an NPC could get two sets of volumes ("four diaries, each name twice", **verified**) because nothing tracked volumes still being created, so recovery, catch-up and diary events each created the same volumes; creations are now counted per actor and cancelled at every load and Reset. The create queue no longer stalls after a failed dispatch or when a load drops an in-flight Create(). DiaryDB is closed at kPreLoadGame, the co-save's folder name is ignored, a new game's first save marks its volumes persisted, volumes that reach past a loaded save are reconciled with the history SkyrimNet kept or cleared (ReconcileWithTimeline, replacing the game-time stale rebuild, which missed saved volumes after an in-session revert and dropped new entries), an empty template name no longer blocks an actor, and the actor cache and book timers hold FormIDs instead of pointers. Crash-proofing: exceptions can no longer escape into the engine from the book-open hook, the post-load sync (which now always re-enables diary events), the save and load callbacks, the theft event sink, the Papyrus natives, the inter-plugin handler or the SkyrimNet API wrappers. Config values are clamped when read, so EntriesPerVolume = 0 in the INI no longer hangs the game, and a non-numeric INI value no longer wipes the INI on the next save. Identity: theft and return detection work in every language (the English "Diary" name filter and the name-in-title owner fallback are gone; volumes are found by base FormID and owners by UUID), the Nightingale journal is chosen by base NPC instead of English name, a book opened after a load-order change no longer shows another actor's entries (the stored actor FormID is checked against the UUID), and the two startup warnings are localized. Text: dates use Skyrim's real month lengths instead of 30-day months; diary prose is escaped for the book markup (a "<" no longer swallows text, and a literal [pagebreak] can't shift the API's entry numbering); Win-1251 conversion only runs on Cyrillic text (French «» are no longer mangled) and now also maps „ and №; the inter-plugin API header describes what the handlers actually return. Also removed that day: the in-game `ExtraUniqueID` probe, the unused `DPF_API` shim, the `PhysicalDiaryAPI` and `GetStolenFaction` natives, a log-only duplicate container sink and the `SNDC` co-save cache it fed, Dynamic Book Framework-era `.txt` cleanup, and about a dozen uncalled functions.

## Likely bugs (user-facing)

1. **A volume whose entries were all deleted keeps its old text.** `RefreshVolumeOnOpen` returns early when the live count is 0 and cached text exists (to protect imported or test books), which skips the "all entries removed" re-render after a deletion outside a load (a timeline Clear at load is now reconciled). Needs a real signal, such as a "never had API entries" flag, instead of treating a count of 0 as imported. See [VOLUMES_AND_SYNC.md](VOLUMES_AND_SYNC.md#save-reverts-the-keep--clear-fork).
2. **Reset leaves books in unloaded cells as untracked orphans.** `ResetAllDiariesInternal` removes books only from references in loaded cells and (deliberately) does not dispose the forms. A book lying in a far-away container stays in the game, untracked, and would open showing its template's own text.
3. **After a Keep revert, an entry dated inside the latest volume is dropped if the NPC no longer holds that volume.** It can't start a new volume without overlapping the previous one's dates, so `UpdateDiaryForActorInternal` logs a warning and skips it. See [VOLUMES_AND_SYNC.md](VOLUMES_AND_SYNC.md#when-an-entry-arrives-updatediaryforactorinternal).

## Robustness and performance

4. **One detached thread per created book** (`DPFCreateCallback`: sleep 5 s, then clear `kCantTake`). A catch-up scan creating hundreds of volumes parks hundreds of sleeping threads. Use one timer or a game-thread deadline queue.
5. **"Sealed" means three things.** Reaching `EntriesPerVolume` in `UpdateDiaryForActorInternal`; "a newer volume exists" in `RefreshVolumeOnOpen`; `endTime > 0` in `QueueSealedVolumeRecovery`. `endTime` is set on every volume, so the recovery's "open volume" branch (`endTime == 0`) only runs for legacy rows. It still behaves correctly, but the naming misleads.
6. **`GetBookForFormID` is a linear scan** over every volume, and it runs on every book container change and every book open. Keep a FormID → volume index next to `books_`.

## Tech debt

7. **The co-save does no real work.** `SNDB` is a two-zero sentinel. `SNDF` is written and read, but the value is thrown away at `kPostLoadGame`. Removing the co-save changes the save format; do it on purpose. See [DATABASE.md](DATABASE.md#co-save-records).
8. **The version says 1.0.0** in `CMakeLists.txt` and `vcpkg.json`, but v1.1.0 has shipped.
9. **Unused ESP record** `SNPD_DiaryStolenFaction` (from a faction-based theft design). ESP edit.
10. **VR fixes untested on VR:** `ClearBogusSourceFiles` / `SanitizeLoadedBookForms` (`BookCreation.cpp`) and `useDefaultPos` (`BookTextHook.cpp`) need a VR test. Also find where DPF's `0x1` comes from.
11. **Hand-written inline hook.** `BookTextHook::Install` decodes the target's prologue itself. A detour library would be sturdier across runtime updates.
12. `GetDiaryTheftStatus` always returns `"chronicled": false`, left over from an older design. Public API, so change it carefully.
13. **`TimelineGate` is a stopgap.** It recognises SkyrimNet's keep/clear prompt by comparing message text and wraps its callback, because SkyrimNet's public API can't say whether its timeline check is still pending. When SkyrimNet adds that (e.g. `PublicIsTimelineCheckPending()`), use it and keep the hook only as the fallback for older SkyrimNet versions. See [VOLUMES_AND_SYNC.md](VOLUMES_AND_SYNC.md#waiting-for-the-decision-timelinegate).
14. **A DPF FormID can mean different diaries in different saves.** DPF reuses FormIDs once a loaded save doesn't contain them, so the same FormID can be one NPC's diary in an older save and another NPC's in DiaryDB. SNPD re-applies its own name and look on load, but if the older save put that form in a different NPC's inventory, that NPC now holds a book showing the other diary. Deterministic per-volume FormIDs (DPF RE) would remove this; see the open decision below.

## Open decision

15. **Stay on DPF, move to DPF RE, or write our own.** DPF's two known bugs (unsafe allocator, duplicate recycled records) are handled (see [BOOK_FORMS.md](BOOK_FORMS.md#the-two-dpf-bugs-this-pipeline-works-around)). DPF RE would make book FormIDs deterministic, but has open questions (whole-registry rewrite on every create, thread safety, whether forms exist in time for `.ess` inventory). Per-instance identity and an ESL pool were tested and rejected. See [BOOK_FORMS.md](BOOK_FORMS.md#alternatives-evaluated).
